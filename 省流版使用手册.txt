二、关闭

   Windows: 双击 shiki-stop.cmd
   Linux:   bash stop.sh

二点五、换模型 + API 密钥（改 config.yaml 就行）

   所有启动入口都读 config.yaml + skills/shared/llama_config.py，无硬编码模型路径。
   换模型只需改三行：

     llama_model:      "E:\\新模型.gguf"     # GGUF 路径（唯一真源）
     llama_model_name:  "新模型名"            # API alias，留空自动取文件名
     llama_model_id:    "llama/新模型名"      # model id，留空自动=local/<名>

   API 密钥（安全和可扩展）：
     llama_api_key:     "123456"             # 改自己的；留空则不加 --api-key
     - 设置后推理接口要求带 Authorization: Bearer <key>（/health 仍免认证探活）
     - headroom/sakura/shiki_daemon 自动带 key，不用额外配
     - 接入 CCR 时，CCR 的 provider 也要填相同 api_key

   自动机制（不用手动调）：
     - model_profiles 按文件名关键字自动匹配启动参数（q4_0/batch/cpu_moe/MTP/rea）
     - 模型名含 mtp → 自动加 --spec-type draft-mtp（非mtp不会误加）
     - llama_model_id 后缀跟 name 不一致时 → 自动校准（防残留旧值）

   停启验证：
     python skills\shared\llama_lifecycle.py stop 8080
     python skills\shared\llama_lifecycle.py start 8080
     curl http://127.0.0.1:8080/v1/models   # 看 alias 对不对

三、调试（九层，从下往上查）

    1.GPU层   → 浏览器打开 http://127.0.0.1:8080/health 看llama活着没
    2.代理层  → http://127.0.0.1:19251/api/status 看 headroom-proxy（mem0+压缩 for OpenClaw）
    3.桌宠层  → Live2D看 http://localhost:19200/api/status ；Sakura直接看桌面
    4.桥接层  → http://127.0.0.1:19250/api/status 看 Artemis Bridge（TTS+ComfyUI API，不管LLM）
    5.能力层  → 直接跑 skills/tts/tts_call.py 或 skills/comfyui/comfyui_call.py 或 skills/asr/asr_call.py <音频文件>
    6.中枢层  → openclaw gateway status ；日志在 %TEMP%\openclaw\
    7.MCP层   → python .claude/artemis_mcp_server.py 然后粘贴 JSON-RPC 请求测试
    8.任务层  → http://127.0.0.1:19280 看 AgentRQ 风格任务队列
    9.网关层  → Shiki Daemon 面板 http://127.0.0.1:19260 看全部服务状态

常见坑：
    - llama起不来 → config.yaml里llama_exe/llama_model路径对不对
    - OpenClaw本地模型超时 → 检查headroom-proxy: http://127.0.0.1:19251/api/status ；重启: python artemis_headroom_proxy.py --port 19251
    - 图片/语音只返回路径没文件 → 跑一下 sync_qqbot_workspace.py
    - Artemis Bridge TTS/画图失败 → 检查 http://127.0.0.1:19250/api/status
    - Sakura闪退 → 进 skills/sakura/ 手动跑 start.bat 看报啥错
    - Task Board打不开 → 检查 python .claude/task_board_api.py 是否在跑 (:19280)
    - Claude Code MCP工具超时 → 单独跑 .claude/artemis_mcp_server.py 看有没有报错
